      WHAT THIS APP DOES
      TSM Shell is an AI-assisted copilot for working service desk tickets end to end — from intake through root-cause analysis, specialist troubleshooting, resolution write-up, and escalation. Instead of switching between separate tools and cheat sheets, everything lives in one place: paste in a ticket, let the AI read it, get pointed to the right specialist workspace for the actual issue, and walk out with a documented resolution or a ready-to-send escalation package. The exec strip at the very top (Today's Tickets, Resolved, Open, SLA %, Vendor Cases, Repeat Issues) is a live snapshot of your queue, and the floating chat bubble in the bottom-right corner is always available for a quick question — you don't need to be on a specific tab to use it.
      THE STRIP AT THE VERY TOP — DECISION JOURNEY
      Above the tabs sits a second, thinner bar — TSM Copilot Decision Journey — which is not another tab, it's a guided overlay on top of the same ticket. It's the app coaching you through the mental sequence a strong L1 tech already runs unconsciously, broken into five checkpoints: UNDERSTAND (read the ticket before touching anything else), ASSESS (don't take the submitted priority at face value — challenge it against what the ticket actually describes), EXPLAIN (be able to state the evidence for your read, not just the conclusion), ACT (commit to a next best action), and HUMAN DECISION (the AI's suggestion is a draft, not an instruction — you decide). Two extra anchor buttons, TICKET and CONTEXT / CMDB, jump straight to the asset/warranty fields without advancing the sequence, and an ESCALATE anchor jumps to the Escalation tab the same way.

      Think of the tab sidebar as where the work happens and the Decision Journey strip as the order of thinking that should be behind it, regardless of which tabs you actually open. If the strip's current step doesn't match what you're doing — e.g. it's still on UNDERSTAND but you're already deep in Troubleshooting — that's usually a sign you skipped the reasoning step, not just the UI step.

      The A+ LEARN / PRACTICE / READINESS / TIMED EXAM / TROUBLESHOOTING LAB / PBQ SIM links in that same bar open the separate A+ certification training suite in a new tab. They're not required to work a ticket — they exist so that when something in a real ticket exposes a gap (an unfamiliar RAID level, an APIPA address you had to look up), you can jump straight into deliberate practice on that exact topic instead of just moving on. See Cert Prep in this sidebar for how the whole training suite maps onto the A+ → Network+ → Security+ → Azure Fundamentals ladder.

      WORKING THE QUEUE — RECOMMENDED ORDER
      1. Ticket → paste the full ticket text as soon as it lands, before you touch the hardware or remote in. The AI reads best on raw, unfiltered user language — running analysis will also pull any incident #, asset, manufacturer, or warranty details it finds straight into the fields above, so you don't need to re-type what's already in the text.
      2. AI Analysis → run it immediately after intake. Treat Confidence as a triage signal, not a verdict — below ~70%, expect to spend more time in Troubleshooting before you trust the recommended path.
      3. Troubleshooting → work the checklist in order (Verify User → Power → Hardware → OS). Skipping ahead because you "know" the fix is the single biggest cause of re-opened tickets — the checklist exists so nothing gets assumed.
      4. Imaging / AD & Intune / SCCM / VMware SME / Cloud Ops → open whichever specialist tab matches what the checklist pointed to, not all of them by habit. Imaging for OSD builds stuck on PXE, partitioning, or driver injection; AD / Intune for compliance drift, BitLocker escrow, or Autopilot enrollment issues; SCCM for a failed or stuck Software Center deployment; VMware SME for anything touching vCenter, vRA/vRO, Cloud Director, NSX, or IaC provisioning; Cloud Ops for Azure/AWS resources or the VMware-on-cloud stack (AVS, VMC on AWS, GCVE). Jumping straight to Vendor Support on a provisioning or deployment issue means missing the fix that's native to the tool that actually owns it.
      5. Vendor Support → pull this up the moment hardware is implicated, even if you think it's software. Knowing the warranty tier before you need it saves the hold-time later.
      6. SLA → check this every time you switch tabs, not just when the alert bar fires. Color changes are your cue to act, not a background indicator.
      7. Notes → review what auto-populated from the checklist before you move to Resolution. Edit anything the AI got wrong instead of deleting it — an accurate note is what makes the History record trustworthy later.
      8. Resolution → generate this before you close the ticket, not after — it forces you to confirm the actions taken actually match what's in Notes.
      9. Escalation → if you reach this tab, you should already know why — it should confirm your reasoning, not create it from scratch.
      STAYING AHEAD OF SLA
      GREEN Plenty of runway — work the checklist fully, don't shortcut steps to save time you don't need to save.

      AMBER You're inside the window where escalation should already be in motion if L1 hasn't resolved it — open the Escalation tab now, not when it flips red.

      RED Breach is imminent or has happened. Stop troubleshooting, escalate immediately, and note the breach reason in Resolution so the pattern can be tracked — a late escalation is still better than a silent one.

      A P1 with 20 minutes remaining and a P3 with 20 minutes remaining are not the same urgency — always read the Priority field next to the timer, not the timer alone.
      ANOMALY SIGNALS TO WATCH FOR
      Repeat asset/user in History → the same hostname or requester showing up more than once usually means the last fix treated a symptom, not the root cause. Say so explicitly in the new ticket's notes and consider escalating on the second occurrence rather than the third.

      Low confidence + high severity together → this is the highest-risk combination in the queue — the AI isn't sure, but the stakes are high. Don't rely on the recommended path alone; work the full checklist and lean toward earlier escalation.

      Vendor case opened but warranty status unclear → resolve this before dispatch gets involved — an expired warranty discovered mid-repair costs more time than checking it up front.

      Escalations clustering on one team → if Network or Server escalations spike in a short window, that's an infrastructure signal, not a coincidence of unrelated tickets — flag it up rather than closing each ticket independently.
      WHY THESE FOUR, IN THIS ORDER
      A+ → Network+ → Security+ → Azure Fundamentals is the standard entry ladder for desktop/service-desk techs, and it isn't a coincidence that it maps almost exactly onto the tabs in this app. A+ covers the hardware, OS, and troubleshooting work you do in Ticket, Troubleshooting, and Imaging. Network+ covers the connectivity and infrastructure concepts underneath AD / Intune and SCCM. Security+ covers the compliance, encryption, and incident-response thinking behind AD / Intune's BitLocker/compliance fields and the Escalation tab's severity model. Azure Fundamentals (AZ-900) covers the concepts underneath the Cloud Ops tab. None of these exams test this app directly, but every domain they test has a real, working example sitting in a tab you already use — that's the fastest way to make abstract exam objectives stick.

      One honest caveat: exam codes and domain weights below are current as of mid-2026 but CompTIA and Microsoft do revise them every few years. Before you sit any of these, confirm you're studying the exam code your voucher is actually for — always cross-check against the vendor's own current objectives page rather than trusting any single guide, including this one.

      A+ — KEY TERMS & PRACTICE QUESTIONS
      POST
      Power-On Self-Test — hardware diagnostic the system runs before handing off to the OS. No POST beeps + no display = hardware, not software.
      BIOS / UEFI
      Firmware that initializes hardware at boot. UEFI is the modern replacement — supports GPT partitioning and Secure Boot.
      RAID 0 / 1 / 5
      0 = striping, speed only, no redundancy. 1 = mirroring, full redundancy, half capacity. 5 = striping with parity, redundancy with better space efficiency.
      SATA vs. NVMe
      SATA is the older drive interface. NVMe drives connect over PCIe and are dramatically faster — the modern default for SSDs.
      APIPA
      Automatic Private IP Addressing (169.254.x.x) — a device assigns itself this when it can't reach a DHCP server.
      PXE
      Preboot Execution Environment — network boot, used to image machines with no local OS or USB media.
      ESD
      Electrostatic Discharge — anti-static wrist straps/mats protect components before you ever open a case.
      IaaS / PaaS / SaaS
      Cloud service models — Infrastructure / Platform / Software as a Service, by how much the provider manages for you.
      MDM / BYOD
      Mobile Device Management / Bring Your Own Device — Core 2's mobile-device-management objectives.
      UPS
      Uninterruptible Power Supply — battery backup that also conditions/protects against power surges.
      Q1. A laptop shows the manufacturer logo at boot, then goes black. No POST beep codes. What should you check first?
      A) Reinstall the operating system
      B) Reseat RAM and check hardware connections
      C) Run an antivirus scan
      D) Update the browser
      The OS never loaded — the logo screen is firmware, before the OS hands off. Anything software-side (antivirus, browser, OS reinstall) is out of scope until hardware is ruled out.
      Q2. You need to image 30 new laptops that have no OS installed and no USB ports available for media. What's the correct method?
      A) USB flash drive imaging
      B) PXE network boot
      C) Manual install from optical media
      D) System Restore
      No USB ports rules out flash-drive imaging. PXE boots over the network directly to a task sequence — no local media required at all, which is exactly the scenario this app's own Imaging tab models.
      Q3. Which RAID level gives you redundancy with better space efficiency than mirroring, across 4 drives?
      A) RAID 0
      B) RAID 1
      C) RAID 5
      D) JBOD
      RAID 0 has no redundancy at all. RAID 1 mirrors (redundant, but you lose half your capacity). RAID 5 stripes with parity — redundant, but only sacrifices roughly one drive's worth of capacity instead of half.
      Q4. A workstation shows an IP address of 169.254.12.44. What does this tell you?
      A) A static IP was manually misconfigured
      B) DHCP was unreachable, so the device self-assigned via APIPA
      C) DNS resolution failed
      D) There's a duplicate MAC address on the network
      169.254.x.x is the reserved APIPA range. Seeing it means the device tried DHCP, got no response, and fell back to self-assigning — point your troubleshooting at the DHCP server or the path to it, not the workstation's own config.
      Q5. Which drive interface gives the highest throughput for a modern SSD?
      A) SATA III
      B) IDE
      C) NVMe over PCIe
      D) USB 2.0
      NVMe drives talk directly over PCIe lanes instead of the older SATA controller path, which is the whole reason they're dramatically faster.
      Q6. Before opening a desktop case to replace a component, what's the correct first step?
      A) Ground yourself with an ESD strap before touching components
      B) Leave the system plugged in for grounding
      C) Remove only the battery and proceed
      D) No precaution is needed for modern hardware
      ESD can silently damage components without any visible spark. Ground yourself first, every time — modern hardware is not immune to this.
      NETWORK+ — KEY TERMS & PRACTICE QUESTIONS
      TCP vs. UDP
      TCP is connection-oriented and guarantees delivery (file transfers, web). UDP is fast and connectionless, no delivery guarantee (streaming, VoIP).
      DNS
      Domain Name System — translates hostnames to IP addresses.
      DHCP
      Dynamic Host Configuration Protocol — automatically assigns IP addresses to devices on the network.
      NAT
      Network Address Translation — maps private internal IPs to a single public IP for internet access.
      VLAN
      Virtual LAN — logically segments one physical network into isolated broadcast domains.
      CIDR notation
      Subnet size shorthand — e.g. /24 = 256 addresses, /26 = 64 addresses. Formula: 2^(32 − prefix).
      ARP
      Address Resolution Protocol — maps a known IP address to its MAC address on the local segment.
      ICMP
      Internet Control Message Protocol — what ping and traceroute actually run on.
      STP
      Spanning Tree Protocol — prevents switching loops (and the broadcast storms they cause) on redundantly-connected switches.
      PoE
      Power over Ethernet — a single cable carries both data and electrical power, commonly to access points and cameras.
      Q1. Which protocol is connection-oriented and guarantees delivery, making it the right choice for file transfers?
      A) UDP
      B) TCP
      C) ICMP
      D) ARP
      TCP's handshake and acknowledgment process is exactly what guarantees delivery — the tradeoff is more overhead than UDP, which is why UDP is preferred for real-time streaming instead.
      Q2. You need to isolate the Finance department's traffic from the rest of the office, on the same physical switches. What's the right approach?
      A) Install a new NIC in every Finance device
      B) Configure a VLAN for Finance
      C) Change the office Wi-Fi SSID
      D) Enable NAT on the Finance switch
      VLANs create logical separation without needing separate physical hardware — exactly the tool for "same wires, different broadcast domain."
      Q3. A subnet is configured as /26. How many total addresses does that block contain?
      A) 256
      B) 64
      C) 26
      D) 32
      2^(32−26) = 2^6 = 64. Two of those (network and broadcast address) aren't assignable to hosts, so it's 62 usable — but the block itself is 64.
      Q4. Two switches are cross-connected for redundancy and the network suddenly floods with broadcast traffic. What protocol should already be preventing this?
      A) STP (Spanning Tree Protocol)
      B) DHCP
      C) DNS
      D) SNMP
      Redundant switch links without STP create a loop, and broadcast traffic circles forever, multiplying — that's a broadcast storm. STP's whole job is blocking the redundant path until it's needed.
      Q5. The ping command relies on which protocol to test reachability?
      A) SNMP
      B) ICMP
      C) ARP
      D) NTP
      ICMP echo request/reply is literally what a ping is — worth knowing cold since it comes up constantly in both the exam and real troubleshooting.
      Q6. Which technology lets a single Ethernet cable carry both data and electrical power to a wireless access point?
      A) QoS
      B) VLAN
      C) PoE
      D) NAT
      Power over Ethernet — common for APs, IP cameras, and VoIP phones where running a separate power cable isn't practical.
      SECURITY+ — KEY TERMS & PRACTICE QUESTIONS
      CIA Triad
      Confidentiality, Integrity, Availability — the foundational concept nearly everything else in Security+ builds on.
      AAA
      Authentication, Authorization, Accounting — who you are, what you're allowed to do, and the record that you did it.
      MFA / SSO
      Multi-Factor Authentication (something you know + have + are) / Single Sign-On (one login, many systems).
      RBAC / ABAC
      Role-Based Access Control (permissions by job role) vs. Attribute-Based (permissions by dynamic attributes like time, location, device).
      SIEM
      Security Information and Event Management — aggregates and correlates logs across the environment to surface real threats.
      SOAR
      Security Orchestration, Automation, and Response — automates the response playbook once a SIEM flags something.
      EDR / XDR
      Endpoint Detection & Response / Extended Detection & Response — EDR watches endpoints, XDR correlates across endpoints, network, and cloud.
      Zero Trust Architecture
      "Never trust, always verify" — no user or device is trusted by default, even inside the network perimeter.
      IoC
      Indicator of Compromise — observable evidence (unusual traffic, a known-bad file hash) that an attack may be underway.
      RTO / RPO
      Recovery Time Objective (how long you can be down) / Recovery Point Objective (how much data loss is acceptable) — both disaster-recovery planning metrics.
      Q1. A company wants to ensure that even if an employee's password is stolen, an attacker still can't log in. What should be implemented?
      A) SSO
      B) MFA
      C) RBAC
      D) A VPN
      SSO actually reduces friction but doesn't add a second factor — a stolen password still works. MFA specifically requires something beyond the password itself.
      Q2. Which security model assumes no user or device should be trusted by default, even once they're inside the network?
      A) Defense in depth
      B) Zero Trust Architecture
      C) Air-gapping
      D) Role-based access control
      Defense in depth is about layering controls; Zero Trust specifically rejects the old "trusted inside the perimeter" assumption and verifies continuously, regardless of network location.
      Q3. An analyst notices unusual outbound traffic from a server to an unfamiliar external IP at 3am. This is best described as:
      A) An Indicator of Compromise (IoC)
      B) A CVE
      C) An RPO
      D) A DLP policy
      A CVE is a known, catalogued vulnerability in software — not an observed behavior. Unusual traffic at an odd hour is exactly the kind of observable evidence an IoC describes.
      Q4. What does an organization's RTO actually define?
      A) How much data loss is acceptable
      B) How long a system can be down before it must be restored
      C) Who is allowed to access the system
      D) The encryption algorithm in use
      That's RPO, not RTO — a common mix-up. RTO is about downtime duration; RPO is about the data-loss window. Keep them paired but distinct.
      Q5. Which tool aggregates logs from firewalls, servers, and endpoints to correlate events and surface threats in real time?
      A) EDR
      B) SIEM
      C) DLP
      D) PKI
      EDR is endpoint-scoped. SIEM is the aggregation-and-correlation layer across the whole environment — that breadth is the defining feature.
      Q6. Assigning permissions based on a user's job function (e.g., "HR Manager") rather than to each individual person is an example of:
      A) ABAC
      B) RBAC
      C) MFA
      D) Zero Trust
      Role-Based means the role carries the permissions, not the individual. ABAC would instead evaluate dynamic attributes (time of day, device posture, location) at access time.
      AZURE FUNDAMENTALS (AZ-900) — KEY TERMS & PRACTICE QUESTIONS
      IaaS / PaaS / SaaS
      Same cloud service models as A+, applied specifically to Azure's own product lines.
      Resource Group
      A logical container that groups related Azure resources for unified management, billing, and permissions.
      Region vs. Availability Zone
      A region is a geographic area with one or more datacenters; an Availability Zone is a physically separate datacenter within that region, used for high availability.
      Microsoft Entra ID
      Azure's identity service (formerly Azure Active Directory) — handles authentication and identity across Azure and Microsoft 365.
      Azure Policy vs. RBAC
      Policy enforces rules on what resources can be deployed and how they must be configured. RBAC controls what actions specific users/services can perform. One of the most commonly tested distinctions on this exam.
      SLA
      Service Level Agreement — Microsoft's contractual uptime guarantee for a given service.
      CapEx vs. OpEx
      Capital Expenditure (large upfront hardware purchase) vs. Operational Expenditure (predictable ongoing subscription cost) — cloud shifts spend from the former to the latter.
      Scalability vs. Elasticity
      Scalability = a system can grow to handle more load by adding resources. Elasticity = resources auto-adjust up and down with real-time demand.
      High Availability (HA)
      A system's ability to stay operational despite individual component failures.
      Disaster Recovery (DR)
      The plan and process for restoring operations after a major outage — pairs directly with the RTO/RPO concepts from Security+.
      Q1. A company wants to prevent any VM from being deployed without encryption enabled, enforced automatically at deployment time. What should they use?
      A) RBAC
      B) Azure Policy
      C) Availability Zones
      D) Azure Monitor
      RBAC controls who can do what — it doesn't govern how a resource must be configured. Policy is the enforcement mechanism for configuration rules like "encryption required."
      Q2. Which cloud model requires the customer to manage only their applications and data, with the provider handling the OS, runtime, and everything below it?
      A) IaaS
      B) PaaS
      C) SaaS
      D) On-premises
      SaaS hands the customer a finished application — think Microsoft 365 itself. PaaS still has the customer managing their own application code/runtime; IaaS goes even further down to OS management.
      Q3. What's the actual difference between scalability and elasticity?
      A) They mean the same thing
      B) Scalability handles more load by adding resources; elasticity auto-adjusts resources up and down with demand
      C) Elasticity only applies to storage accounts
      D) Scalability is a security feature
      This exact pair is one of the most tested distinctions on AZ-900. Scalability is the capability; elasticity is the automatic, bidirectional behavior.
      Q4. A finance team wants to move from a large upfront hardware purchase to a predictable monthly bill. This is a shift from:
      A) OpEx to CapEx
      B) CapEx to OpEx
      C) PaaS to IaaS
      D) Public cloud to private cloud
      Upfront hardware = Capital Expenditure. A recurring subscription = Operational Expenditure. This is one of the most commonly cited business benefits of cloud adoption.
      Q5. Which Azure construct is a physically separate datacenter within the same region, used to protect against a single datacenter failure?
      A) Resource Group
      B) Availability Zone
      C) Azure Policy
      D) Subscription
      A Resource Group is purely organizational/logical — it has no physical redundancy meaning at all. Availability Zones are the physical, fault-isolated building block.
      Q6. You need to stop a specific user from deleting production resources, while still letting them view those resources. What should you configure?
      A) Azure Policy
      B) RBAC
      C) Azure Monitor
      D) Renaming the resource group
      This is about permissions on an identity, not rules on a resource's configuration — that's the RBAC vs. Policy distinction again, from the other direction.
