Platform Navigation

Finding Your Way Around ServiceNow

Every ServiceNow instance is organized around the Application Navigator — the collapsible left-hand menu listing every module you have access to (Incident, Change, CMDB, Service Catalog, etc.). Use the search bar at the top of it to jump straight to a module without hunting through menus.

Most of your day-to-day work happens in list views — sortable, filterable tables of records (tickets, CIs, changes). Learn to build a filter once and save it as a favorite; you'll reuse it daily.

  • Now Experience UI — the modern workspace layout most agents use day to day

  • Favorites — pin frequently used lists and records for one-click access

Users, Groups & Access

Who Can See and Do What

Access in ServiceNow is controlled by roles, which are assigned to users or bundled into groups. A role like itil grants baseline access to Incident, Problem, and Change; admin-level roles go further.

Access Control Lists (ACLs) are the underlying rules that actually enforce who can read, write, create, or delete a given table or field — roles are how you get matched against those rules.

  • Assignment groups — the team a ticket routes to (e.g. "Network Support")
  • Approval groups — who signs off on a change or request
  • Delegated admins can manage users/groups without full system admin rights

Incident & Problem

Incident Management

An Incident is an unplanned interruption or reduction in quality of a service. Every incident moves through a state model: New → In Progress → On Hold → Resolved → Closed. Priority is calculated from Impact × Urgency — get comfortable reading that matrix, it drives SLA timers.

Problem Management

A Problem record captures the underlying root cause behind one or more incidents. The goal is a Known Error — a documented root cause with a workaround — so future incidents referencing it resolve faster.

  • Major Incident process — a fast-tracked, high-visibility variant of standard incident handling
  • Linking related incidents to a single Problem record avoids duplicated investigation work

Change Enablement

Managing Change Without Breaking Things

ServiceNow classifies changes into three types: Standard (pre-approved, low-risk, repeatable), Normal (requires review and approval, most changes fall here), and Emergency (urgent, expedited approval to fix something actively broken).

The Change Advisory Board (CAB) reviews higher-risk normal changes before they're scheduled. Risk is typically assessed on likelihood and impact — a well-written change record makes this review fast instead of a bottleneck.

  • Change scheduling checks for conflicts against a Change Freeze calendar
  • A rollback/backout plan is expected on any Normal or Emergency change

CMDB & Assets

Configuration Management Database

The CMDB stores Configuration Items (CIs) — servers, applications, network devices, anything you track and manage. CIs are linked together through relationships (e.g. "runs on," "depends on"), which is what lets you see downstream impact before you approve a change.

Asset Management is related but distinct — it tracks the lifecycle of a purchased item (procurement → in use → retired), while the CMDB tracks how that item fits into your service topology.

  • Discovery tools populate and keep CI data accurate automatically
  • Bad CMDB data quality is the #1 reason change risk assessments go wrong

Notifications & Basics

Automation Without Writing Code First

Notifications fire automatically off record changes (e.g. "email the assignee when priority is raised"). UI Policies control what a user sees on a form in real time (show/hide/require fields); Business Rules run server-side logic when a record is inserted, updated, or deleted — the key distinction is UI Policies are client-facing, Business Rules run regardless of who's looking.

Flow Designer is ServiceNow's no-code automation builder — most day-2 admin work (approvals, routing, notifications) can be built here without scripting.

  • Client Scripts run in the browser for immediate form behavior
  • Start with Flow Designer before reaching for a script
