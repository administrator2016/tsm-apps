Month-End Close Workflow

Honest status: this page merge-writes into the same TSM_CONSTRUCTION_STRATEGIST_RELAY key the war-room/strategist chain already uses, so the Construction Executive Portal (which already reads that key) picks up the property-accounting close package with no changes needed on its side. "Feed Exception Queue" calls the real TSMExceptions.add() engine with sector:'construction' — first real producer for this vertical's exception panel, which was previously mounted but unfed (see construction-demo-presentation.html).

Now real, this pass: journal entries actually post (debit/credit against named GL accounts), a running debit/credit total drives a live reconciliation-balanced check, editing the budget recalculates Actual/Variance/KPI cards live, and AP invoices can be individually approved (posts a real offsetting journal entry) or rejected (logged, not posted) instead of only being counted.

Still not implemented: none of this persists past the page session (no backend/database — everything lives in page-local JS state, same as the rest of this demo tier), so a reload resets the ledger. There's no 3-way PO/invoice match, no bank-feed reconciliation against a real bank statement, no cash-vs-accrual basis toggle, no compliance rule engine, no signed audit trail, no mortgage/draw payment processing, and no client-facing statement generator. This is a real double-entry workflow demonstration — not a production accounting system of record.
